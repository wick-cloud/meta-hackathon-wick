# Public hackathon demos

The dedicated `/demos` page provides two sponsored, anonymous journeys: a terminal
demo and a guided Muse Studio Hello World demo. Both use a real Baseten token
auction, a real compute auction with Modal and E2B Micro eligibility, and a live
terminal on a private disk. Judges do not need an account, payment details, Wick
credentials, or a Baseten service key. The homepage describes the customer
product and links to the demos and buyer beta. Both auctions retain their normal 30-second deadlines.
The token auction has one eligible provider: Baseten. The compute auction invites
qualified Modal and E2B Micro supply and displays only bids actually accepted by
the server. Modal's effective bid is **$0.01**, through its operator-funded
provider promotion or a disclosed homepage credit. The receipt shows the original
gross bid and any additional demo credit.
Modal has priority on a one-cent tie. A missing valid Modal bid ends that attempt;
the demo never invents competing bids or silently switches provider or VM size.
The demo uses each invited supplier's valid base bid or fixed provider promotion,
subject to its pricing policy and available capacity. It does not spend extra Muse calls on compute bid
discount proposals; the terminal example demonstrates the real Muse integration.

## Judge experience

1. Open the [Live demos page](https://meta-hackathon-wick-production.up.railway.app/demos) and choose the terminal demo or guided Muse Studio.
2. Watch the token and compute bids, countdowns, and award receipts on the page.
3. **Terminal demo:** once ready, get the demo token key, connect the terminal,
   and run `python3 /workspace/hello_muse.py`. Paste the key at the hidden prompt.
   The script redeems the Baseten pack through the Broker gateway for Muse Spark Open.
4. **Guided Muse Studio:** watch the real model generate `hello_world.py` and the
   VM run and verify it. Inspect the generated code and execution output, then
   rerun `python3 /workspace/hello_world.py` in the terminal. Rerunning this Hello
   World file does not consume another model call.
5. Keep using the terminal for the rest of the 15-minute lease, even after both
   Muse calls are used. Explore files, edit the Python script, or run shell commands.
   Select **End demo** only when finished. Reconnection uses the same VM; closing
   the browser does not stop its lease or extend it. The timer includes VM setup.

In the terminal demo, the key remains in browser memory only, and the script uses `getpass` without
writing it to disk, shell history, or command arguments. Reloading the page may
require replacing the key; replacing it revokes the old key and preserves the
same remaining quota and request limit. Each run allows at most five key issuance
attempts. Requests with unknown upstream outcomes
retain their reservations and cannot be automatically retried.

Guided Muse Studio has a fixed task and a small allowance; it is not the unrestricted
repository workflow available to signed-in Studio customers. Muse generates the
actual Python source. An operator-authored runner accepts only a single literal
`print("Hello, World!")` expression, writes the generated bytes to the private
disk, executes the validated source, and checks the real result. It does not accept
imports, arbitrary commands, repository URLs, or custom prompts. The runner uses
at most one additional model call for a definite invalid response, never for an
uncertain upstream outcome. Task completion or failure does not end the VM lease.

Both variants share visitor/IP admission, concurrency, daily sponsorship, and
cooldown. The selected variant is fixed for a run. Returning from the homepage to
`/demos` resumes that run; it does not purchase another VM or token pack.

## Fixed demo policy

| Resource           | Limit                                                                                                                        |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Compute            | Qualified Modal and E2B Micro bids; exact `modal:micro:auto` award, 15-minute lease including setup, maximum $0.25 gross bid |
| Demo compute price | Modal $0.01 after sponsorship; original gross bid and sponsor contribution disclosed                                         |
| Tokens             | Baseten only, 5,000 input / 2,048 output, maximum $0.05 purchase                                                             |
| Model requests     | At most two accepted attempts per run; at most 1,024 output tokens per request                                               |
| Disk               | One private disk per run; `hello_muse.py` for terminal, generated `hello_world.py` for guided Studio                         |
| Next run           | Both resources unlock 20 minutes after confirmed VM cleanup; pending cleanup remains blocked                                 |
| Concurrent runs    | At most two globally, and one per anonymous identity or observed client IP                                                   |
| Daily sponsorship  | $5 per America/New_York calendar day; reserve $0.50 per admitted run                                                         |

The one-cent display price does not reduce the provider's accepted gross price,
invoice, or commission calculation. If the separate operator-funded Modal provider
promotion is enabled, its genuine gross bid is already one cent and the homepage
adds no further credit. That provider promotion retains its recorded native cost
estimate and subsidy. The homepage still enforces its stricter $0.25 cost-covered
compute ceiling. Judges pay nothing. Normal buyer auctions retain their existing
pricing rules, including any separately configured provider promotion.

The conservative $0.50 reservation covers the compute and token purchase
ceilings plus $0.20 reserved for disk/operational overhead. Once a run attempts
resource work, its reservation remains counted for that day. It is a sponsorship
admission ceiling, not a measurement of upstream invoices. Operators must verify
the native route/storage costs against the reserve before public enablement and
retain their upstream account spending controls.

The anonymous cookie is opaque, HttpOnly and SameSite=Strict (Secure in
production). It authorizes only this demo and its own terminal, never the normal
buyer, Studio, provider, admin, funding, or general API-key workflows. Ordinary
signup remains disabled. Each visitor receives a distinct internal owner, and
each run has its own VM, disk, token grant and purchase receipts.

The server also enforces the cooldown against a keyed digest of the observed
client IP, so clearing cookies does not reset that IP's allowance. Visitors on a
shared network share that restriction. Raw IP addresses are not stored in demo
records. IP changes cannot bypass the global concurrency or daily sponsorship
ceiling. Repeated clicks, parallel tabs and retries cannot create extra resources
for an admitted run.

## Operator setup

Enable `LIVE_DEMO_ENABLED=true` only after deployment and qualification. Keep
`WICK_MODE=real`, `MUSE_MODE=real`, `INFERENCE_MARKET_MODE=real`, and
`DISKS_ENABLED=true`. Configure the existing server-only Wick/Baseten credentials,
an unexpired Baseten request-sized inference accounting certificate, published
automatic-bid token supply, and approved Modal Micro compute supply with a valid
current rate. Also publish qualified E2B Micro supply
with automatic bidding, available capacity, and a gross bid within the $0.25
ceiling. Both routes must satisfy the existing native-disk qualification and
provider-account checks; the demo admits no larger profiles. Additional configured
providers are outside this bounded demo auction. The fixed demo ceilings must
cover the genuine gross offers before sponsorship.

For Railway's public HTTP edge, use the already-supported
`AUTH_TRUST_RAILWAY_PROXY=true` so abuse limits use the edge's sanitized
`X-Real-IP`. Do not enable that trust on unsanitized private/TCP ingress. Without
that setting the demo uses the direct socket address, ignoring arbitrary
forwarding chains.

No provider credential enters the browser or the demo disk. The service performs
one fixed, bounded script bootstrap in the allocated VM and verifies it before
exposing the terminal. It does not expose a public arbitrary-command API.

The durable demo worker reconciles auctions, provisioning, bootstrap, expiry,
key revocation, grant closure, VM cleanup and disk deletion after process
restarts. Per-run disks are deleted only after confirmed detachment; pooled demo disks are retained exclusively for reuse. Unknown native
outcomes remain blocked rather than releasing their global capacity early.
Turning off the feature blocks new admissions and key/terminal access while
cleanup continues.

## Verification and release gate

Offline checks use disposable PostgreSQL schemas and explicit fixture adapters.
They must remain labeled simulations; they do not prove provider availability.
The regression suite covers admission races, cooldown and daily reset,
cross-visitor isolation, cookie/header manipulation, fixed providers and limits,
key replacement, model-request concurrency, and cleanup recovery. Browser checks
cover the homepage and both demos at desktop and narrow mobile widths.

Before public enablement, complete one bounded live journey on the deployed
release: both actual auctions select the intended providers; Modal Micro mounts
the private disk; the preloaded Python script produces a real Baseten/Muse
response; quota and receipts update; and ending the demo confirms VM termination,
key rejection, disk deletion, and the paired cooldown. Include the homepage URL
and these judge instructions alongside the public GitHub repo and demo video.

The opt-in verifier runs that journey through public HTTP and terminal WebSocket
APIs. It allocates one real demo VM/disk, makes two bounded Baseten requests,
checks that a third request is rejected and the terminal still accepts commands
and reconnects without changing the lease, then explicitly ends its own test run
to verify cleanup and cooldown. Ordinary judge sessions stay open after token
exhaustion until their lease expires or the judge selects **End demo**.
It requires no provider or account credentials and never logs the key or terminal
text. Do not force-kill it during cleanup.

```sh
APP_URL=https://meta-hackathon-wick-production.up.railway.app npx tsx scripts/verify-homepage-demo.ts --live
```

The guided Studio verifier uses the same limits and cleanup path. It waits for a
real generation and verified execution receipt, then reruns the generated file
through the live terminal and compares its on-disk SHA-256 with the model source.
It also checks that task completion and terminal reconnection leave the original
lease and model usage unchanged. It does not issue a token key.

```sh
APP_URL=https://meta-hackathon-wick-production.up.railway.app npx tsx scripts/verify-homepage-demo.ts --live-studio
```

Run only one live verifier at a time and honor the shared cooldown between runs.
Use `--self-test` without `APP_URL` for parser checks with no network calls.

## Reusable demo disks

Production may enable `LIVE_DEMO_REUSE_DISKS=true`. The demo worker pre-creates
at most two dedicated disks per integration mode. Both demo choices use this same
pool. Existing customer disks are never adopted. Each disk is leased exclusively;
the next visitor cannot claim it until native VM termination and zero native
attachments are confirmed. Ending a run closes its token grant and VM but retains
the demo disk. The next VM clears all workspace files, including hidden files and
prior Studio journals, before installing its instructions or allowing terminal or
model access. A failed or uncertain reset never exposes the terminal.

Disk creation is removed from subsequent runs; the two real auction deadlines,
VM startup and mount confirmation still apply. The initial pool must finish
provisioning before it is warm. Disabling reuse stops new checkouts, while existing
pooled runs still release their exclusive leases safely. Persistent storage remains
allocated to this bounded demo pool until explicitly retired by an operator.
